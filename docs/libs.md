# Pure libs

Read to find which lib owns a behaviour, or before adding to a pure lib. Moved from CLAUDE.md unchanged.

**Pure libs (no DOM):**

- `src/lib/ascii/egg.js` — `potArt` renderer + confetti. Ported verbatim from the prototype; tune only while looking at output.
- `src/lib/ascii/banner.js` — ANSI Shadow "DANNY HU".
- `src/lib/ascii/image.js` — project media's ASCII: `structureLevels` (grey levels → ramp digits, by distance from the median, with a noise floor; used at build time), `gridRows` (a stored grid fitted to a width), `revealOrder` / `revealCount` (the seeded random, stepped uncover; `seedFrom` makes the seed from a media key) and `scrambleFrame` (the private placeholder), `test/asciiImage.test.mjs`.
- `src/lib/media.js` — a project's media for drawing: `mediaKey` (the one place the `<slug>/<file>` key is made: the grids, the page and the shell use it) and `mediaItems` (a project's `media` → picture sources, size and grid; a missing grid throws), `test/media.test.mjs`.
- `src/lib/shell/{fs,spec,exec,history}.js` — virtual FS, `SPEC` table, `createShell(data)` → `{ exec, runLine, complete }`, `histStep` (↑/↓ through a session's history). Takes content as an argument (no `@/` imports), so it runs under plain node. `src/lib/shell/index.js` wires in the real data.
- `src/lib/vim.js` — terminal-mode vim as a pure state machine (`openBuffer`, `vimKey(state, key, ctrl)` → next state + effects); `clipNote` turns the system clipboard's answer to a yank into its status-line note (the register is independent of it): normal/visual/visual-line/command-line/search modes, motions, `d`/`y` operators, registers, put, undo/redo. Edits stay in memory.
- `src/lib/keyRouter.js` (every keydown's decision, see Keyboard model), `src/lib/selection.js` (the j/k stops and selection steps, `selectionLabel`: what the live region reads for the hero), `src/lib/urls.js` (section and project URLs, `parseHash`/`parsePath`), `src/lib/typeInStart.js` (when a section types in, see Section headers), `src/lib/projectHistory.js` (project-page history decisions, see GUI mode), `src/lib/dates.js` (`isCurrent`: experience date ranges like `sep 2026 – dec 2026`), `src/lib/format.js` (`pad`, `lc`, `joinParagraphs`, `projectRowName`), `src/lib/focusWrap.js` (`wrapTab`: where Tab goes inside a popup, `test/focusWrap.test.mjs`), `src/lib/linkClick.js` (when a click on an app link stays in the app and when it is the browser's, `test/linkClick.test.mjs`), `src/lib/bootProject.js` (`isProjectAddress`: the layout's boot script uses its source, `test/bootProject.test.mjs`), `src/lib/pageLock.js` (the fixed-body lock for shells, and `setPopupLock`: `html.popup-lock` for a popup, which doesn't fix the body), `src/lib/useStickToBottom.js` (the shell pane pins its output to the latest prompt).
- **GitHub data is build-time only.** `scripts/sync-github.mjs` (its pure parts, tested, in `scripts/github-snapshot.mjs`; a repo that answers 404 is dropped, other failures keep the previous entry and its old `syncedAt`; the file keeps `reposAt` and `activityAt` apart from `attemptedAt`, a cached file is validated before reuse and the write is atomic; the repos are read from the structured `projects` data by the one parser in `src/lib/githubUrl.mjs`, loaded under plain node by `scripts/load-projects.mjs`) runs as `prebuild` / `predev` and writes `src/data/github.generated.json` (gitignored): repo metadata for every GitHub link in `projects.js` plus 12 weeks of activity. `src/lib/github.js` reads it (`spark`, `repoFor`, `syncedAt`: when the repo records were last really fetched). Visitors never call the GitHub API; the sync never fails the build and keeps the previous snapshot on errors. `scripts/check-repos.mjs` (separate from the sync; decisions in the pure `repoDrift` and `driftReport` of `github-snapshot.mjs`, tested) is the repo check: see `docs/deploys.md`.
- `src/lib/egg/held.js` (`heldAfter`: when a tap holds the egg and what lets go, `test/eggHeld.test.mjs`), `src/lib/egg/fit.js` (`eggFit`: the terminal egg block's height and the pot's scale on a phone, `test/eggFit.test.mjs`), `src/lib/egg/screen.js` (the touch and phone media queries, `isTouch`/`isPhone`/`useIsTouch`: the one place that decides what a touch phone is; reads the DOM, so not in the pure libs), `src/lib/egg/paint.js` (DOM helper: writes a `potArt`/`rollArt` frame into a `<pre>` plus colour layers; used by the minigame and the 404), `src/lib/egg/roll.js` (rolling-egg physics: a solid egg rolling without slipping or energy loss; energy gives ω(θ), one integration gives a time table, runtime is a lookup, so the ends dwell longer than the sides; `restTime` is the pose on its side and `nextStop` the last time within a roll limit it lies there, which is where the 404 egg stops), `src/lib/ascii/roll.js` (its renderer, time in → string out), `src/lib/egg/game.js` (clock, grading, stats, and `paintDue`: whether the hero egg paints at this timestamp, 30/s or 15/s once idle; it takes the timestamps, so it is pure), `src/lib/egg/counter.js` (eggs cooked on this device, localStorage only; no network), `src/lib/github.js` (reads the build-time snapshot: `spark`, `repoFor`, `syncedAt`, date formatting; no runtime API calls), `src/lib/skills.js` (`buildItems`, `buildSkills`: the three-source skill bars, `test/skills.test.mjs`), `src/lib/resumeView.js` (the resume viewer's zoom steps and fit), `src/lib/resumeKeys.js` (its key decisions and the shared `ACTION` names), `src/lib/resumeLinks.js` (the PDF's link rectangles as boxes over the canvas), `src/lib/resumePinch.js` (pinch, the scroll that anchors a zoom, double-tap, Ctrl+wheel) and `src/lib/resumePrint.js` (`printMode`: frame or tab), each with a test; `resumeView.js` also holds `zoomFor`/`FOLLOW` (what a followed zoom wants for a room).
