# Redirect stubs, 404 and the resume page

Read before changing a redirect stub, the 404 or the resume viewer. Moved from CLAUDE.md unchanged.

- `src/app/{projects,experience,skills}/page.js` are redirect stubs to the matching anchor (static export has no server redirects): `components/Redirect.jsx`, a meta refresh plus a link, no client code, `noindex`, and `alternates: {}` so they don't inherit the layout's home canonical. The layout carries a schema.org Person (JSON-LD).
- **404**: `src/app/not-found.js` → `components/notfound/NotFound.jsx`, which the static export writes to `404.html` (GitHub Pages serves it for every unknown URL, so the shown path comes from `window.location`, not props: basePath stripped and decoded, `~/café`). It prints a failed `cd` in the shell's voice over `RollingEgg`: one egg rolling right over ground scrolling back under it (physics in `src/lib/egg/roll.js`, frames from `src/lib/ascii/roll.js`). It rolls for at most 5s (WCAG 2.2.2) and stops on its side at the last rest moment that fits (`nextStop`, so the pose is the reduced-motion frame, not a freeze mid-tumble); a click on the egg, `r` (not with shortcuts off) or the `[r] roll again` button, which shows only while it rests, rolls it again for up to 5s more. One still frame under reduced motion, with no replay. Pinned by the browser check (`the 404 egg rests…`, `reduced motion: the 404 egg…`). Enter goes home. Its metadata sets `alternates: {}` and `robots: null` so the page has only Next's own `noindex` (the layout's `index, follow` would be a second, contradicting robots meta). The link-preview card is `public/og-card.png` (1200×630, drawn by `scripts/make-icons.mjs` with the favicon egg; `site.ogImage` holds its absolute URL and every page's `openGraph` and `twitter` list it, with `summary_large_image`): Next's own `opengraph-image` file under `basePath` doubled it (`/Portfolio/Portfolio/`) and the resume and project pages, which set their own `openGraph`, lost it. `npm run check:head` (`scripts/check-head.mjs`, also a CI step after the build) reads `out/*.html` and pins the head of every sitemap page, the stubs and the 404.
- **Resume page**: `/Portfolio/resume/` (`src/app/resume/page.js` → `components/resume/ResumeViewer.jsx`, standalone like the 404, not the App) draws `public/Danny_s_Resume.pdf` with pdf.js (`pdfjs-dist`, pinned exact, imported only there and only in an effect: it needs the browser). Every "resume ↗" (bottom bar, `r`, the shell's `xdg-open resume.pdf`) opens it in a new tab: `site.resume` is the page, `site.resumePdf` the file. Per page: a canvas drawn off screen and swapped in (so two renders never share one; `canvas.width/height` must be set from the viewport, `render()` doesn't; at least 1700px across so printing isn't soft, at most 12M pixels because iOS leaves a bigger canvas blank), a selectable text layer (pdf.js's `.textLayer` CSS cut down in the module, spans sized through `--total-scale-factor`) and the file's links as `<a>`s over it (`linkBoxes`, web and mail addresses only). The worker is `new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)`: Turbopack emits it under `/Portfolio/_next/static/media/`, and a module worker needs `.mjs` served as JavaScript (GitHub Pages does; the browser check's server has an entry for it). The zoom follows the room (a `ResizeObserver` on the stage: a turned phone, a resized window, the document's scrollbar appearing once the pages are in) while it is the opening fit or a fit asked for, and stays put once the visitor zooms by hand; a zoom step redraws after a 100ms pause (a held `+` draws once) and the old text layer is re-scaled at once so selection keeps lining up; the page sets `html.kbd` itself (the app's `Cursor` does that, and isn't here) so its `html:not(.kbd)` hover rules work. **Pinch**: the stage has `touch-action: pan-x pan-y` and `components/resume/useZoomGestures.js` turns two fingers into the viewer's own zoom (smooth, 25–300%, `pinchZoom`), so the label and the page follow and the toolbar doesn't grow; pointer events keep arriving for both fingers under `pan-x pan-y` (a spike on a mobile-emulated Brave: 12 moves each, no `pointercancel`), and one finger still scrolls. The zoom is anchored with `anchorDelta` to the spot that was under the fingers when they landed, not to the previous frame (early frames can't scroll yet, and a frame-to-frame anchor never made that up). A double-tap flips fit ↔ 100% (`doubleTap`), and Ctrl+wheel (a trackpad pinch in Chrome and Firefox: a native non-passive `wheel` listener; the delta is normalised by `deltaMode`, since Firefox reports a mouse wheel in lines) and Safari's `gesture*` events (untested: WebKit only) do the same on a laptop; events that arrive before the screen catches up build on `targetRef` (the zoom asked for), not on what is drawn, and a zoom with no point to keep (`setZoomFree`) drops any pin a gesture left waiting; a pinch's capture starts only with the second finger, because a captured pointer redirects the click and a tap must reach a link. Two fingers that both start in the toolbar are still the browser's own page zoom, so the toolbar can always be magnified (never `touch-action: none` or `user-scalable=no`; the browser only starts a native pinch after a wider finger span than ours needs, which the check accounts for). The toolbar is the nav's split: leave (`[esc] cd ~`) on the left, the file name in the middle (a three-column grid, so it is centred on the screen; under 800px the tools take a row of their own), the tools on the right. `download` and `print` are bordered buttons like the home page's terminal / theme / keys (`.btn`), the zoom steps are the bare `[-]` and `[+]` (their own labels, not key hints, so they show on touch and with shortcuts off), and the controls are `inline-block` because `inline-flex` strips the space after a key hint. There is no page indicator (the file has one page; the page objects are kept, so adding it back is a few lines). **Esc leaves** (`ACTION.LEAVE`, it works with shortcuts off like the app's Esc): `leave` closes the tab when it has an opener, which lands back on the app's tab, and goes home in place where the browser refuses (a 250ms fallback: Firefox won't close a link-opened tab) or the visitor came straight here. The app's own resume links keep their opener for that (`openTab` in `App.jsx` for the `r` key and the shell, `rel="opener"` on the bottom bar's link: a plain `target=_blank` implies noopener); other sites' tabs never do. Controls like a basic reader: zoom steps, fit, download (`Danny_Hu_Resume.pdf`), print (the PDF file itself: `printPdf` loads it in a hidden frame, or opens it in a tab where `printMode` says a frame is unreliable: Safari, every iPhone browser, a touch screen, no inline PDF viewer; Cmd+P still prints the page through `@media print`, from a canvas that is at least 1700px across), keys `+ - 0 d p` through `resumeKey` (all off with single-character shortcuts, held `d`/`p` act once); a key or a touch flashes its control through `pressFx` (`data-action` finds the button) and, at ≤600px, each control reaches a 44px row through an invisible `::before` while staying text-sized. The page stays white paper in both themes. **The PDF must carry no phone number or school email** (`test/resume.test.mjs` reads its streams): export a clean copy before replacing it.
