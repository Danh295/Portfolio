# Keyboard model and accessibility

Read before changing a key, a shortcut, the j/k selection, focus, a popup, the live region or shortcuts-off. Moved from CLAUDE.md unchanged.

- **Keyboard model**:
  - **Key router**: every keydown is decided by the pure `src/lib/keyRouter.js`. App reads the facts of the key and the page (`keyFacts`), `routeKey` returns one decision, and App's `applyKey` carries it out with no conditions of its own. The order of the router's checks is this model, pinned by `test/keys.test.mjs`. A new shortcut is a `KEYS` entry plus its `keys` in a `src/config/ui.js` row, which a test cross-checks.
  - **Stops and selection**: each section's header is its first stop and the only thing with the blinking cursor; j/k then move through its elements (hero: `more…`, the egg; work/experience: rows), which show as inverted with no cursor. ←/→ move like k/j on the main page (on a project page they step between projects). `m` opens more…. Skills are stops too (`skillSel`, one per skill; `SKILL_NAMES` in `src/lib/selection.js`). **Focus follows the selection and the other way** (WAI-ARIA "one point of focus"; the sequential-focus starting point moves with `focus()`, not with scrolling): a j/k move gives real focus (`focusStop`, quiet) to the selected project row, role button, skill row or, for a header stop, the section's `<h2 tabIndex={-1}>`, so the next Tab goes on from it; a row or heading that takes focus by Tab or a click becomes the selection (`followFocus`, on `focusin`; a skill's panel opens only for a focus Tab made, via `tabFocus`, not `:focus-visible`); a selection made by a held press (`pointerHeld`) doesn't scroll the row into view, since that would lose the click, and a key or a window blur drops the flag if the release never came. Esc with nothing left to close clears the selection and moves focus to the section's heading, so the two never split. The hero's stops stay a highlight read out by the live region (`selName`, hero only); rows carry their position as hidden text ("project 2 of 10"), skill rows in their `aria-label`.
  - **Enter/Space** activate the selected element (Space scrolls when nothing is selected), except that a link or button reached with Tab keeps its own Enter/Space (App records what Tab focused; not `:focus-visible`, which Chrome turns on for a clicked button at the first keypress); focus a click left behind doesn't, so a timed egg press never goes astray.
  - **Key repeat**: toggle, open and activate keys ignore it (`noRepeat` in the router's `KEYS`; a held `t` would strobe the theme); moving keys repeat.
  - **Popups**: while the keys, more… or (phone) menu popup is open it owns the keyboard: only Esc, `?`/`m` (which swap between them) and `s` (keys popup) act; scroll keys (and Cmd+↑/↓, to its ends) scroll the popup's `[data-popup-scroll]` list instead of the page; Enter/Space press a focused button in it; other Cmd/Ctrl/Alt combinations stay the browser's (Alt/Cmd+←/→ are Back/Forward). Only a plain `` ` `` toggles the shell.
  - **Project pages**: ←/→ replace the history entry and leaving never adds one, so one Back always leaves the project pages. A `#hash` deep link skips the boot intro.
  - **Press flash**: every activation by key (including shortcuts with a visible `data-key` button) or touch flashes the element via `src/lib/pressFx.js`; a mouse click doesn't (the hover look just holds while pressed and after the click, so nothing flickers).
  - **Egg**: played only through its buttons (the centre start box, then one button under the pot that the "start!" callout turns into); clicking the pot itself only pans.
  - **Single-character shortcuts can be turned off** (WCAG 2.1.4): `[s]` in the keys popup (or `s` while it's open), or `set keys on|off` in the shell; saved in `localStorage` (`danny-keys`) by `src/lib/useKeysPref.js`, mirrored on `<html data-keys>` (the pre-paint script in `layout.js` sets it too, so nothing flashes). While off, `html[data-keys="off"] [data-hint]` hides every hint for a one-character key: wrap new `[x]` hints in `<Hint>` (`src/components/Hint.jsx`, trailing space inside; hints for esc, enter, arrows and tab, which still work with shortcuts off, go in `<KeyLabel>` instead: hidden on touch only), and the keys popup lists only the rows in `src/config/ui.js` that still work. On touch screens (`(hover: none) and (pointer: coarse)`, a static media query in `globals.css`: never `html.kbd`, which would resize the page under a jump) every key label is hidden: `[data-hint]` and `[data-keyhint]` (`<KeyLabel>` wraps the labels for esc, enter, arrows and tab; `<TouchText>` is the wording that takes their place, e.g. "tap to start", shown on touch only). An iPad with a keyboard counts as touch (no media query sees a keyboard), so the `keys` button stays and its popup can still turn shortcuts off. The shells' output is 14px on touch and their prompt 16px scaled to look the same (iOS zooms the page when a smaller field takes focus), and `a, button` carry `touch-action: manipulation` (no double-tap zoom, so the timed egg buttons answer at once). Off ignores every one-character key (letters, digits, `?`, `` ` ``, j/k) in the key router, and the terminal's 0–9 shortcuts type into the prompt instead; Enter, Space-on-selection, arrows, Backspace and Esc always work, and the header/bottom-bar buttons still do everything.
- **Accessibility conventions:**
  - **Popups** (keys, more…, the phone's menu) share one frame, `components/overlay/Popup.jsx` (scrim, `┤ label ├` head naming the dialog, `[esc] close`, the `[data-popup-scroll]` body, a foot slot): it focuses its box on open and returns focus on close (kept across a `?`↔`m` swap); App makes header, main, bottom bar and the embedded shell `inert` while one is open.
  - **Focus moves** (all via `focusQuiet`: no scroll, no focus ring): closing the shell focuses the header terminal button, opening a project focuses its `[data-detail-title]` h1, and closing focuses the row of the project last shown (else the selected row).
  - **Announcements**: the j/k selection sets `aria-current` and is read out by one polite live region in `App.jsx` (`selName`). Shell output sits in `role="log"`. A focusable element whose `data-tip` is its only detail gets `data-tip-focus` (Tooltip shows it on keyboard focus too, even in keyboard mode).
  - `test/contrast.test.mjs` keeps `--fg`/`--mid` ≥ 4.5:1 on `--bg` and `--soft` in both themes. The intro takes all keys while it plays except Cmd/Ctrl combinations (Esc/Enter/Space skip it).
