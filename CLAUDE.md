# Project Instructions

Personal portfolio site for Danny Hu. Next.js 16 (App Router) + React 19, JavaScript (no TypeScript), CSS Modules, static-exported to GitHub Pages at `/Portfolio/`.

## Architecture

**v4 design: terminal-style, one client app.** `src/app/page.js` renders `src/components/App.jsx`, the single `"use client"` root that holds all UI state (theme, gui/terminal mode, project filter/selection, open project, experience accordion, vim, help; the shell sessions live in `useShell`). The design reference lives in `design_handoff_portfolio_v4/` (README + prototype HTML); it is ignored by eslint and prettier.

- **GUI mode**: `Header`, four `SectionFrame`s (`#home` hero + egg, `#projects`, `#experience`, `#skills`), `BottomBar`. Open project = `ProjectDetail` (state).
  - **Each project is a real page**, `/Portfolio/projects/<slug>/`: `src/app/projects/[slug]/page.js` pre-renders `<App initialView={slug} />` with its own title, description and canonical, and the sitemap lists them. Inside the app, sections are hashes on the home page (`/Portfolio/#experience`).
  - **Project history** is owned by `src/lib/useProjectHistory.js`, which applies the pure decisions in `src/lib/projectHistory.js` (tested in `test/history.test.mjs`): opening from the list `pushState`s the path and saves the list's scroll position (`listY`) on the home entry; stepping replaces; Esc / [back] / Backspace on a project this page load opened `history.back()`s to that entry (a per-load token, since `history.state` outlives a reload); every other way out (a section jump, the shell, a deep-linked project) replaces with the section. Back to a home entry with `listY` restores it exactly. Old `/#projects/<slug>` links are rewritten to the path.
  - Next's router accepts these native history calls without remounting the app (checked: shell history and state survive back/forward).
- **Keyboard model**:
  - **Key router**: every keydown is decided by the pure `src/lib/keyRouter.js`. App reads the facts of the key and the page (`keyFacts`), `routeKey` returns one decision, and App's `applyKey` carries it out with no conditions of its own. The order of the router's checks is this model, pinned by `test/keys.test.mjs`. A new shortcut is a `KEYS` entry plus its `keys` in a `src/config/ui.js` row, which a test cross-checks.
  - **Stops and selection**: each section's header is its first stop and the only thing with the blinking cursor; j/k then move through its elements (hero: `more…`, the egg; work/experience: rows), which show as inverted with no cursor. ←/→ move like k/j on the main page (on a project page they step between projects). `m` opens more….
  - **Enter/Space** activate the selected element (Space scrolls when nothing is selected), except that a link or button reached with Tab keeps its own Enter/Space (App records what Tab focused; not `:focus-visible`, which Chrome turns on for a clicked button at the first keypress); focus a click left behind doesn't, so a timed egg press never goes astray.
  - **Key repeat**: toggle, open and activate keys ignore it (`noRepeat` in the router's `KEYS`; a held `t` would strobe the theme); moving keys repeat.
  - **Popups**: while the keys or more… popup is open it owns the keyboard: only Esc, `?`/`m` (which swap between the two) and `s` (keys popup) act; scroll keys (and Cmd+↑/↓, to its ends) scroll the popup's `[data-popup-scroll]` list instead of the page; Enter/Space press a focused button in it; other Cmd/Ctrl/Alt combinations stay the browser's (Alt/Cmd+←/→ are Back/Forward). Only a plain `` ` `` toggles the shell.
  - **Project pages**: ←/→ replace the history entry and leaving never adds one, so one Back always leaves the project pages. A `#hash` deep link skips the boot intro.
  - **Press flash**: every activation by key (including shortcuts with a visible `data-key` button) or touch flashes the element via `src/lib/pressFx.js`; a mouse click doesn't (the hover look just holds while pressed and after the click, so nothing flickers).
  - **Egg**: played only through its buttons (the centre start box, then one button under the pot that the "start!" callout turns into); clicking the pot itself only pans.
  - **Single-character shortcuts can be turned off** (WCAG 2.1.4): `[s]` in the keys popup (or `s` while it's open), or `set keys on|off` in the shell; saved in `localStorage` (`danny-keys`) by `src/lib/useKeysPref.js`, mirrored on `<html data-keys>` (the pre-paint script in `layout.js` sets it too, so nothing flashes). While off, `html[data-keys="off"] [data-hint]` hides every hint for a one-character key: wrap new `[x]` hints in `<Hint>` (`src/components/Hint.jsx`, trailing space inside; hints for esc, enter, arrows and tab stay plain text), and the keys popup lists only the rows in `src/config/ui.js` that still work. Off ignores every one-character key (letters, digits, `?`, `` ` ``, j/k) in the key router, and the terminal's 0–9 shortcuts type into the prompt instead; Enter, Space-on-selection, arrows, Backspace and Esc always work, and the header/bottom-bar buttons still do everything.
- **Accessibility conventions:**
  - **Popups** (keys, more…) share one frame, `components/overlay/Popup.jsx` (scrim, `┤ label ├` head naming the dialog, `[esc] close`, the `[data-popup-scroll]` body, a foot slot): it focuses its box on open and returns focus on close (kept across a `?`↔`m` swap); App makes header, main, bottom bar and the embedded shell `inert` while one is open.
  - **Focus moves** (all via `focusQuiet`: no scroll, no focus ring): closing the shell focuses the header terminal button, opening a project focuses its `[data-detail-title]` h1, and closing focuses the row of the project last shown (else the selected row).
  - **Announcements**: the j/k selection sets `aria-current` and is read out by one polite live region in `App.jsx` (`selName`). Shell output sits in `role="log"`. A focusable element whose `data-tip` is its only detail gets `data-tip-focus` (Tooltip shows it on keyboard focus too, even in keyboard mode).
  - `test/contrast.test.mjs` keeps `--fg`/`--mid` ≥ 4.5:1 on `--bg` and `--soft` in both themes. The intro takes all keys while it plays except Cmd/Ctrl combinations (Esc/Enter/Space skip it).
- **Section headers** (`src/lib/useTextFx.js`, trigger `"active"`) type once per page load, when the pure `src/lib/reveal.js` (`test/reveal.test.mjs`) says so, by how the page got there (`src/lib/jump.js`, `<html data-jump>`), not the input device (`html.kbd` only pauses hover): after the user scrolls or clicks (`none`: wheel, trackpad, touch, scrollbar, Space/PageDown), a section starts once `REVEAL_PX` (120px, AOS's default offset) of it shows between the nav and the bottom bar; while a jump scrolls (`moving`: nav buttons, `1`–`4`, `h`, j/k, the shell, a deep link) and after it has `landed`, only its target (the active section) starts, the moment its header is fully on screen, mid-scroll included, so arriving never waits on the jump to settle (once landed, `REVEAL_PX` showing also counts, in case layout moved under the jump); the sections it flies past, and one peeking below, wait to be selected or scrolled to. Nothing that toggles with the selection may change a section's height (the hero's cursor is a zero-width box for this): a jump's target is computed before it scrolls. Focus moving into a waiting section starts it at once. The band comes from `src/lib/bars.js` (App fires `BARS_MEASURED` when the nav or bar resizes, so the observers rebuild). A header counts as played as soon as it starts and always runs to the end, so it never replays; renders read that through `usePlayed` (a `useSyncExternalStore` over the played set), never the set itself. Everything else in the frame types in with it (`SectionFrame` + `src/lib/typeIn.js`). Until then the frame, title span or hero h1 is `data-fx="pending"`: the real text stays in the DOM (screen readers, find-in-page, crawlers) and `html.fx [data-fx="pending"]` in `globals.css` only makes it transparent, from the first paint (the pre-paint script sets `html.fx` when motion is allowed; a fail-safe removes it after 8s if the app never sets `<html data-hydrated>`). When the header starts, the frame's text nodes are blanked to same-width spaces, un-hidden and typed back in, all in one task. Headings carry `aria-label`s, since their typed text can be blank.
- **Terminal Enter**: a focused button or link handles its own Enter (e.g. `[exit] back to gui`, links from `cat contact.vcf`); otherwise Enter runs the prompt. In the gui, typing while the embedded shell is open but unfocused goes back to its prompt instead of firing shortcuts.
- **Section jumps** park frames at `--nav-offset` = the measured nav height (`--nav-h`, App.jsx) + 26px; section labels are `<h2>`s that name their `<section>`.
- **No scroll snap**: page scrolling is native everywhere; only section jumps (nav, `1`–`4`, `h`, j/k) land exactly, through `scroll-margin-top: var(--nav-offset)`. Don't reintroduce snapping: Chrome's proximity pull reaches about ⅓ of the viewport from each snap point, so with sections shorter than the screen it captures ~75% of every gap (measured at 1291×808: swipes up to ~260px snap back, a read-through with 150px swipes never leaves the top). Mandatory + `scroll-snap-stop: always`, proximity, and a JS settle after `scrollend` (a pause, then a jump in speed) were all tried and dropped.
- **Keyboard mode** (`html.kbd`, set by any keypress, cleared by a real mouse move or any click) pauses hover styling: every `:hover` rule is written as `html:not(.kbd) … :hover` (`:global(...)` in modules). Don't use `pointer-events: none` for this; it swallows clicks.
- **Cursor** (`components/overlay/Cursor.jsx`): one state machine (arrow/pointer/text/busy/pan), two sets: square blocks in gui mode that morph between shapes with a short ease-out (~0.14s, no trailing; difference-blended; the pointer square and the pan outline spin steadily, the pan one round a fixed centre dot), the retro pixel glyphs in terminal mode.
- **Terminal mode** (`./app --mode terminal`): `components/shell/Terminal.jsx` + `Vim.jsx`. The embedded shell (`` ` `` key) is `MiniShell.jsx`. Both frame one `ShellPane.jsx`: the output log (`TermLines.jsx`, `role="log"`) and the prompt under it, kept pinned to the latest prompt (`src/lib/useStickToBottom.js`), with a click focusing the prompt unless it ended a drag-select; `variant` (`term`/`embed`) picks the prompt text (`promptText` in `spec.js`, shared with past prompts), labels and sizing. Both shells' state and keys (sessions, history, autotyped shortcuts, the inline ./egg) live in `components/shell/useShell.js`; a command's effects on the page (open a project, theme, scroll to a section…) come back to App through `onFx` → `applyFx`.
- **App.jsx helpers:** URLs, the scroll lock and quiet focus moves are in `src/lib/nav.js` (`holdNav` sets the jump state to `moving`, its timeout to `landed`, `freeNav` (the user took over) to `none`; `src/lib/jump.js` fires `JUMP_CHANGED`); the j/k selection model (stops, one per experience role) is the pure `src/lib/selection.js` (the key router calls it for j/k); keyboard decisions are the pure `src/lib/keyRouter.js` (`test/keys.test.mjs`). `test/nav.test.mjs` covers the URL parsing (`parseHash`/`parsePath`) and the selection model; the DOM helpers (`holdNav`, `alignTarget`, `focusQuiet`) are untested.
- **Egg minigame**: `components/egg/useEggGame.js` runs one rAF loop that draws into the hero `<pre>` or the terminal's inline one. Per-frame state stays in refs, never React state; only stage/result/stats are state. During a round (stages 1–4) the game logic runs every frame whether or not the pot is on screen (only the raster is skipped); at rest (stage 0 or 5) the loop idles while the pot is off screen or the tab hidden, or once a reduced-motion frame is painted, and any scroll, resize, key, pointer, popstate, stage or mode change wakes it. Every per-frame step is scaled by elapsed time, so speed doesn't depend on the display's refresh rate. The character grid (resolution) comes from `ui.eggFontPx` via `src/lib/egg/grid.js`; smaller font = more cells in the same frame.
- `src/app/{projects,experience,skills}/page.js` are redirect stubs to the matching anchor (static export has no server redirects): `components/Redirect.jsx`, a meta refresh plus a link, no client code, `noindex`. The layout carries a schema.org Person (JSON-LD).
- **404**: `src/app/not-found.js` → `components/notfound/NotFound.jsx`, which the static export writes to `404.html` (GitHub Pages serves it for every unknown URL, so the shown path comes from `window.location`, not props: basePath stripped and decoded, `~/café`). It prints a failed `cd` in the shell's voice over `RollingEgg`: one egg rolling right forever, the ground scrolling back under it (physics in `src/lib/egg/roll.js`, frames from `src/lib/ascii/roll.js`). One still frame under reduced motion. Enter goes home.

**Pure libs (no DOM):**

- `src/lib/ascii/egg.js` — `potArt` renderer + confetti. Ported verbatim from the prototype; tune only while looking at output.
- `src/lib/ascii/banner.js` — ANSI Shadow "DANNY HU".
- `src/lib/shell/{fs,spec,exec,history}.js` — virtual FS, `SPEC` table, `createShell(data)` → `{ exec, runLine, complete }`, `histStep` (↑/↓ through a session's history). Takes content as an argument (no `@/` imports), so it runs under plain node. `src/lib/shell/index.js` wires in the real data.
- `src/lib/vim.js` — terminal-mode vim as a pure state machine (`openBuffer`, `vimKey(state, key, ctrl)` → next state + effects): normal/visual/visual-line/command-line/search modes, motions, `d`/`y` operators, registers, put, undo/redo. Edits stay in memory.
- `src/lib/keyRouter.js` (every keydown's decision, see Keyboard model), `src/lib/selection.js` (the j/k stops and selection steps), `src/lib/reveal.js` (when a section types in, see Section headers), `src/lib/projectHistory.js` (project-page history decisions, see GUI mode), `src/lib/dates.js` (`isCurrent`: experience date ranges like `sep 2026 – dec 2026`), `src/lib/format.js` (`pad`, `lc`, `joinParagraphs`), `src/lib/useStickToBottom.js` (the shell pane pins its output to the latest prompt).
- **GitHub data is build-time only.** `scripts/sync-github.mjs` (its pure parts, tested, in `scripts/github-snapshot.mjs`; a repo that answers 404 is dropped, other failures keep the previous entry) runs as `prebuild` / `predev` and writes `src/data/github.generated.json` (gitignored): repo metadata for every GitHub link in `projects.js` plus 12 weeks of activity. `src/lib/github.js` reads it (`spark`, `repoFor`, `syncedAt`). Visitors never call the GitHub API; the sync never fails the build and keeps the previous snapshot on errors.
- `src/lib/egg/paint.js` (DOM helper: writes a `potArt`/`rollArt` frame into a `<pre>` plus colour layers; used by the minigame and the 404), `src/lib/egg/roll.js` (rolling-egg physics: a solid egg rolling without slipping or energy loss; energy gives ω(θ), one integration gives a time table, runtime is a lookup, so the ends dwell longer than the sides), `src/lib/ascii/roll.js` (its renderer, time in → string out), `src/lib/egg/game.js` (clock, grading, stats), `src/lib/egg/counter.js` (eggs cooked on this device, localStorage only; no network), `src/lib/github.js` (reads the build-time snapshot: `spark`, `repoFor`, `syncedAt`, date formatting; no runtime API calls), `src/lib/skills.js` (share-of-projects bars).

**Static export.** `next.config.mjs` sets `output: "export"`, `images.unoptimized: true`, and `basePath: "/Portfolio"` in production. No server runtime. For asset URLs use `src/config/site.js` (`site.resume` already includes `basePath`).

## Conventions

- **Path alias**: `@/*` → `src/*` (see `jsconfig.json`).
- **Styling**: CSS Modules per component. Five theme tokens (`--bg --fg --mid --line --soft`) in `src/app/globals.css`, switched by `<html data-theme>` via `src/lib/useTheme.js`; default is dark (ink). Radius 0, no shadows except the embedded shell and the popups. Font is IBM Plex Mono, self-hosted from `src/app/fonts/plex/` via `next/font/local` (`--font-plex`), with JetBrains Mono Regular as a per-glyph fallback for the few symbols Plex lacks (■ □ ●); both have a 0.6em advance, which the ASCII art and egg grid assume. `--mono` is the stack. Two weights only: 400 and 500 (headings); there is no bold, and `font-synthesis: none` stops the browser faking one. Don't use Google-hosted fonts: their subsets drop the box-drawing/block glyphs (U+2500–259F). Plex has no ↵ or ★, so use ↲ for Enter. **Casing is stored exactly as displayed** (no `text-transform`, no JS case changes), so the gui and terminal always match: the site's voice is lowercase, including Danny's name, his own project names, job titles, dates and locations ("waterloo, on"); external entities keep their normal casing (companies, schools, events, products and tech: IESO, City of Waterloo, UofTHacks, GitHub, Next.js) as do acronyms (OCR, AI, BBA, UTC).
- **React Compiler is on** (`reactCompiler: true` in `next.config.mjs`, `babel-plugin-react-compiler`): it memoizes components, hooks and JSX at build time, so an embedded-shell keystroke re-renders only the shell (measured). Keep it effective: build big JSX pieces outside conditionals (App.jsx builds `header`, `hero`, `projectList`… up front; `ProjectDetail` and `Terminal` stay inline because each is a single element that depends on `view`/`mode`), don't read the clock or other impure values during render, and never add an `eslint-disable` for a react-hooks rule (the compiler then skips that whole component or hook).
- **Lint rules**: eslint-config-next 16 enables the React Compiler hook rules (`refs`, `set-state-in-effect`, `immutability`, `purity`). Pass refs as top-level `*Ref` props (not nested in objects), and set state from callbacks, not synchronously in effect bodies. **ESLint 10 runs with two workarounds in `eslint.config.mjs`** because `eslint-config-next` 16.3.8 and its plugins (`eslint-plugin-react` 7.37.5, `import` 2.32.0, `jsx-a11y` 6.10.2) don't declare ESLint 10 support yet: JS/JSX files use ESLint's own parser (`espree`, a direct devDependency) because Next's bundled Babel parser crashes on ESLint 10, and `settings.react.version` is pinned because `eslint-plugin-react` autodetects it through `context.getFilename()`, which ESLint 10 removed. Remove both once those packages release ESLint 10 support (check `npm view eslint-config-next peerDependencies` and the plugins' peer ranges); a plugin that starts calling another removed API fails loudly (a crash on lint), not silently.
- **Current role**: an experience entry's `now` (the `● now` badge) is derived from its `date` against the build date (`BUILD_DATE`, `env` in `next.config.mjs`), and the hero/whoami `working` fact shows only while its `org` has a current role, so the daily deploy retires both the day after a term ends.
- **Data**: All content is hand-authored in `src/data/` (`projects.js`, `experience.js`, `home.js`, `egg.js`) and `src/config/` (`site.js`, `ui.js` for design options + shortcuts). There is no CMS.
- **Skills**: `coreTechStack` in `src/data/home.js`. A skill's bar = share of projects whose `tags` include it (exact or prefix word). Skills used by no project show `coursework`; list the courses in that item's `courses` array.
- **Reduced motion**: `src/lib/useReducedMotion.js` is the source of truth. It skips the intro and heading effects and freezes the egg orbit.

## Commands

```
npm run dev           # local dev server
npm run lint          # eslint . (fails on any warning)
npm run format        # prettier --write .
npm run format:check  # prettier --check .
npm test              # node:test suites in test/ (pure libs + data checks)
npm run build         # next build → out/
npm run sync          # refresh the build-time GitHub snapshot
```

**Deploys.** `.github/workflows/pages.yml` runs `lint`, `format:check`, `test` and `build` and deploys `out/` with GitHub's Pages artifact actions on every push to `main`, daily at 09:17 UTC (refreshing the GitHub snapshot; the previous snapshot is restored from the actions cache first, so an API failure keeps the last good data) and on `gh workflow run pages.yml`. Settings → Pages → Source must be **GitHub Actions**. A red check on `main` means nothing was deployed. There are no pull-request checks and no Dependabot: dependency and action bumps are by hand (see the lockfile rule below). GitHub disables scheduled workflows after 60 days with no repo activity, which would silently stop the daily deploy (and the `● now` retirement it drives); `gh workflow enable pages.yml` turns it back on. Node version: `.nvmrc`.

**Tests** (`test/*.test.mjs`) import the app's modules unchanged through `test/hooks.mjs`, which resolves `@/` and extensionless imports like Next does and loads `src/**/*.js` as ESM. Keep the pure libs free of DOM and React so they stay testable. The coursework test is a `todo` until the `courses` arrays are filled.

**Lockfile:** write it only with CI's npm (`npx npm@11.19.0 install --package-lock-only`). A local `npm install`/`npm prune` with another npm version drops the `@emnapi/*` entries and `npm ci` then fails in CI.
