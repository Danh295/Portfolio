# Project Instructions

Personal portfolio site for Danny Hu. Next.js 16 (App Router) + React 19, JavaScript (no TypeScript), CSS Modules, static-exported to GitHub Pages at `/Portfolio/`.

## Architecture

**v4 design: terminal-style, one client app.** `src/app/page.js` renders `src/components/App.jsx`, the single `"use client"` root that holds all UI state (theme, gui/terminal mode, project filter/selection, open project, experience accordion, vim, help; the shell sessions live in `useShell`). The design reference lives in `design_handoff_portfolio_v4/` (README + prototype HTML); it is ignored by eslint and prettier.

- **GUI mode**: `Header`, four `SectionFrame`s (`#home` hero + egg, `#projects`, `#experience`, `#skills`), `BottomBar`. Open project = `ProjectDetail` (state).
  - **Phone bars** (≤600px, by width): the nav is one ~44px row, `~/danny` and the three section links plus a labelled `menu` button, the five spread evenly across the row like the bottom bar's links (`.links` is `display: contents` so they're all flex items of one `space-between` row; the gaps are even, ~15px at 390 and ~7px at 360, where the text itself takes most of the room); terminal / theme / keys move into the menu popup (`components/overlay/MenuModal.jsx`, App's `menuOpen`, a third popup in the `Popup` frame: Esc closes it, `?`/`m` swap to the others, a row closes it first). The bottom bar stays pinned, one ~44px row, with the sparkline left out. Where hints show (a narrow desktop window) or under ~340px a bar may wrap to two rows (a row gap keeps it legible); taps reach the row's height through an invisible `::before`, so a selected chip stays text-sized. The embedded shell panel fills the space between `--nav-h` and `--bar-h`. **Phone hero** (≤600px, `Hero.module.css`): the heading is `clamp(28px, (100vw − 74px) / 8.4, 40px)` so `hey, i'm danny` stays one line from 320px (74px = page padding + intro padding + border, 0.56em per character; change either and the constant moves), and the spacing is tightened so, at 390×844, the egg panel's title peeks in above the bottom bar (a first screen that looks finished hides what's below it); the browser check pins both. **Phone project page and lists**: above a project the `← cd ..`, `←` and `→` buttons share one row (≤600px; 44px tall; the neighbouring project's name moves to the button's `aria-label` and `data-tip`, with a `TouchText` arrow on touch), and on touch the folder filter rows are 28px tall (the `├──` lines break a little between rows). `html` has `scroll-padding-bottom: var(--bar-h)` so a Tab-focused element isn't hidden under the bar (WCAG 2.4.11); never a `scroll-padding-top`, which would add to the sections' `scroll-margin-top` and move where a jump parks.
  - **Each project is a real page**, `/Portfolio/projects/<slug>/`: `src/app/projects/[slug]/page.js` pre-renders `<App initialView={slug} />` with its own title, description and canonical, and the sitemap lists them. Inside the app, sections are hashes on the home page (`/Portfolio/#experience`).
  - **Project history** is owned by `src/lib/useProjectHistory.js`, which applies the pure decisions in `src/lib/projectHistory.js` (tested in `test/history.test.mjs`): opening from the list `pushState`s the path and saves the list's scroll position (`listY`) on the home entry; stepping replaces; Esc / [back] / Backspace on a project this page load opened `history.back()`s to that entry (a per-load token, since `history.state` outlives a reload); every other way out (a section jump, the shell, a deep-linked project) replaces with the section. Back to a home entry with `listY` restores it exactly. Old `/#projects/<slug>` links are rewritten to the path.
  - Next's router accepts these native history calls without remounting the app (checked: shell history and state survive back/forward).
- **Keyboard model**:
  - **Key router**: every keydown is decided by the pure `src/lib/keyRouter.js`. App reads the facts of the key and the page (`keyFacts`), `routeKey` returns one decision, and App's `applyKey` carries it out with no conditions of its own. The order of the router's checks is this model, pinned by `test/keys.test.mjs`. A new shortcut is a `KEYS` entry plus its `keys` in a `src/config/ui.js` row, which a test cross-checks.
  - **Stops and selection**: each section's header is its first stop and the only thing with the blinking cursor; j/k then move through its elements (hero: `more…`, the egg; work/experience: rows), which show as inverted with no cursor. ←/→ move like k/j on the main page (on a project page they step between projects). `m` opens more….
  - **Enter/Space** activate the selected element (Space scrolls when nothing is selected), except that a link or button reached with Tab keeps its own Enter/Space (App records what Tab focused; not `:focus-visible`, which Chrome turns on for a clicked button at the first keypress); focus a click left behind doesn't, so a timed egg press never goes astray.
  - **Key repeat**: toggle, open and activate keys ignore it (`noRepeat` in the router's `KEYS`; a held `t` would strobe the theme); moving keys repeat.
  - **Popups**: while the keys, more… or (phone) menu popup is open it owns the keyboard: only Esc, `?`/`m` (which swap between them) and `s` (keys popup) act; scroll keys (and Cmd+↑/↓, to its ends) scroll the popup's `[data-popup-scroll]` list instead of the page; Enter/Space press a focused button in it; other Cmd/Ctrl/Alt combinations stay the browser's (Alt/Cmd+←/→ are Back/Forward). Only a plain `` ` `` toggles the shell.
  - **Project pages**: ←/→ replace the history entry and leaving never adds one, so one Back always leaves the project pages. A `#hash` deep link skips the boot intro.
  - **Press flash**: every activation by key (including shortcuts with a visible `data-key` button) or touch flashes the element via `src/lib/pressFx.js`; a mouse click doesn't (the hover look just holds while pressed and after the click, so nothing flickers).
  - **Egg**: played only through its buttons (the centre start box, then one button under the pot that the "start!" callout turns into); clicking the pot itself only pans.
  - **Single-character shortcuts can be turned off** (WCAG 2.1.4): `[s]` in the keys popup (or `s` while it's open), or `set keys on|off` in the shell; saved in `localStorage` (`danny-keys`) by `src/lib/useKeysPref.js`, mirrored on `<html data-keys>` (the pre-paint script in `layout.js` sets it too, so nothing flashes). While off, `html[data-keys="off"] [data-hint]` hides every hint for a one-character key: wrap new `[x]` hints in `<Hint>` (`src/components/Hint.jsx`, trailing space inside; hints for esc, enter, arrows and tab, which still work with shortcuts off, go in `<KeyLabel>` instead: hidden on touch only), and the keys popup lists only the rows in `src/config/ui.js` that still work. On touch screens (`(hover: none) and (pointer: coarse)`, a static media query in `globals.css`: never `html.kbd`, which would resize the page under a jump) every key label is hidden: `[data-hint]` and `[data-keyhint]` (`<KeyLabel>` wraps the labels for esc, enter, arrows and tab; `<TouchText>` is the wording that takes their place, e.g. "tap to start", shown on touch only). An iPad with a keyboard counts as touch (no media query sees a keyboard), so the `keys` button stays and its popup can still turn shortcuts off. The shells' output is 14px on touch and their prompt 16px scaled to look the same (iOS zooms the page when a smaller field takes focus), and `a, button` carry `touch-action: manipulation` (no double-tap zoom, so the timed egg buttons answer at once). Off ignores every one-character key (letters, digits, `?`, `` ` ``, j/k) in the key router, and the terminal's 0–9 shortcuts type into the prompt instead; Enter, Space-on-selection, arrows, Backspace and Esc always work, and the header/bottom-bar buttons still do everything.
- **Accessibility conventions:**
  - **Popups** (keys, more…, the phone's menu) share one frame, `components/overlay/Popup.jsx` (scrim, `┤ label ├` head naming the dialog, `[esc] close`, the `[data-popup-scroll]` body, a foot slot): it focuses its box on open and returns focus on close (kept across a `?`↔`m` swap); App makes header, main, bottom bar and the embedded shell `inert` while one is open.
  - **Focus moves** (all via `focusQuiet`: no scroll, no focus ring): closing the shell focuses the header terminal button, opening a project focuses its `[data-detail-title]` h1, and closing focuses the row of the project last shown (else the selected row).
  - **Announcements**: the j/k selection sets `aria-current` and is read out by one polite live region in `App.jsx` (`selName`). Shell output sits in `role="log"`. A focusable element whose `data-tip` is its only detail gets `data-tip-focus` (Tooltip shows it on keyboard focus too, even in keyboard mode).
  - `test/contrast.test.mjs` keeps `--fg`/`--mid` ≥ 4.5:1 on `--bg` and `--soft` in both themes. The intro takes all keys while it plays except Cmd/Ctrl combinations (Esc/Enter/Space skip it).
- **Heading boxes contain their cursor's ink**: the hero's and a project's `h1` carry `padding: 0.3em 0; margin: -0.3em 0`. The "type" effect draws a full-block cursor (`█`, a fallback font's glyph) that sticks out ~0.2em below and above the line box, and iOS Safari repaints only the box, so a strip of the block was left under the first letter on load ("hey, i'm_danny") until the page scrolled; the browser check measures the glyph's ink with the heading's own font. Don't remove the padding or change one without the other (the margin cancels it, so nothing moves).
- **Section headers** (`src/lib/useTextFx.js`, trigger `"active"`) type once per page load, when the pure `src/lib/typeInStart.js` (`test/typeInStart.test.mjs`) says so, by how the page got there (`src/lib/jump.js`, `<html data-jump>`), not the input device (`html.kbd` only pauses hover): after the user scrolls or clicks (`none`: wheel, trackpad, touch, scrollbar, Space/PageDown), a section starts once `START_PX` (120px, AOS's default offset) of it shows between the nav and the bottom bar; while a jump scrolls (`moving`: nav buttons, `1`–`4`, `h`, j/k, the shell, a deep link) and after it has `landed`, only its target (the active section) starts, the moment its header is fully on screen, mid-scroll included, so arriving never waits on the jump to settle (once landed, `START_PX` showing also counts, in case layout moved under the jump); the sections it flies past, and one peeking below, wait to be selected or scrolled to. Nothing that toggles with the selection may change a section's height (the hero's cursor is a zero-width box for this): a jump's target is computed before it scrolls. Focus moving into a waiting section starts it at once. The band comes from `src/lib/bars.js` (App fires `BARS_MEASURED` when the nav or bar resizes, so the observers rebuild). A header counts as played as soon as it starts and always runs to the end, so it never replays; renders read that through `usePlayed` (a `useSyncExternalStore` over the played set), never the set itself. Everything else in the frame types in with it (`SectionFrame` + `src/lib/typeIn.js`). Until then the frame, title span or hero h1 is `data-fx="pending"`: the real text stays in the DOM (screen readers, find-in-page, crawlers) and `html.fx [data-fx="pending"]` in `globals.css` only makes it transparent, from the first paint (the pre-paint script sets `html.fx`, reduced motion included; a fail-safe removes it after 8s if the app never sets `<html data-hydrated>`). When the header starts, the frame's text nodes are blanked to same-width spaces, un-hidden and typed back in, all in one task. Headings carry `aria-label`s, since their typed text can be blank.
- **Terminal Enter**: a focused button or link handles its own Enter (e.g. `[exit] back to gui`, links from `cat contact.vcf`); otherwise Enter runs the prompt. In the gui, typing while the embedded shell is open but unfocused goes back to its prompt instead of firing shortcuts.
- **Section jumps** park frames at `--nav-offset` = the measured nav height (`--nav-h`, App.jsx) + 26px; section labels are `<h2>`s that name their `<section>`.
- **No scroll snap**: page scrolling is native everywhere; only section jumps (nav, `1`–`4`, `h`, j/k) land exactly, through `scroll-margin-top: var(--nav-offset)`. Don't reintroduce snapping: Chrome's proximity pull reaches about ⅓ of the viewport from each snap point, so with sections shorter than the screen it captures ~75% of every gap (measured at 1291×808: swipes up to ~260px snap back, a read-through with 150px swipes never leaves the top). Mandatory + `scroll-snap-stop: always`, proximity, and a JS settle after `scrollend` (a pause, then a jump in speed) were all tried and dropped.
- **Keyboard mode** (`html.kbd`, set by any keypress, cleared by a real mouse move or any click) pauses hover styling: every `:hover` rule is written as `html:not(.kbd) … :hover` (`:global(...)` in modules). Don't use `pointer-events: none` for this; it swallows clicks.
- **Cursor** (`components/overlay/Cursor.jsx`): one state machine (arrow/pointer/text/busy/pan), two sets: square blocks in gui mode that morph between shapes with a short ease-out (~0.14s, no trailing; difference-blended; the pointer square and the pan outline spin steadily, the pan one round a fixed centre dot), the retro pixel glyphs in terminal mode.
- **Terminal mode** (`./app --mode terminal`): `components/shell/Terminal.jsx` + `Vim.jsx`. The screen is `position: fixed` to the part of the screen the visitor can see: `src/lib/useVisualViewportFrame.js` sets `--vv-top`/`--vv-h` (the `visualViewport`) and `data-kb` while a phone keyboard is up (the pure `src/lib/viewportFrame.js` `frameFor` decides, tested with a real iPhone's numbers in `test/viewportFrame.test.mjs`: a keyboard is up only while the prompt has focus AND the visible area is 150px+ shorter than the tallest height seen in this orientation (`nextBaseline`). On an iPhone the keyboard opens in two steps, `visualViewport.height` dropping first and then `innerHeight` itself shrinking while the page scrolls, so `innerHeight − visualViewport.height` is 337 and then 0 and can't be the test; found with a temporary `?vvlog` phone telemetry, commits `26c6b53` and `0b9c5d5`, since reverted: revert the reverts to bring it back), so iOS Safari panning the page to reveal the prompt can't slide the header off the top; with `data-kb` the shortcut bar is hidden (parked below the visible area it still showed in the strip iOS 26 leaves above the keyboard, under Safari's address pill) and the output re-pins to the prompt (`useStickToBottom`). The embedded shell panel uses the same hook (`lock: "keyboard"`: the page locks only while a keyboard is up) and, with `data-kb`, fills the visible area inset 8px. On touch the page doesn't rubber-band (`overscroll-behavior-y: none`: the bounce moved the pinned nav and bar), and both shells' output is 14px with the prompt looking the same: it stays 16px, because iOS zooms the page when a field under 16px takes focus and only reads the computed size, and is scaled to 0.875 (`transform`, from its left edge) so it reads as 14px; its row is the height of a printed line (`line-height` 1.55 × 14px in the embedded shell, 1.6 × 14px in terminal mode), or pressing Enter, which turns it into a printed line, shifted the text by the 3px a 16px line is taller. Typing in or focusing a shell's prompt returns its output to the bottom even after scrolling up (`useStickToBottom`). While a shell has the keyboard up the page is `html.locked`: iOS lets a page with a keyboard open be dragged by up to the keyboard's height (measured: scrollY 0 to 216 under the pinned nav and bar, which teleported), so a locked page takes only pinch zoom (`touch-action: pinch-zoom`), the gui's nav and bar are hidden, and a shell's own scroll box is `pan-y` with `overscroll-behavior: contain` so a drag at its end can't carry on to the page. A keyboard still counts for 700ms after its prompt loses focus (iOS hands the screen back about half a second later; treating that gap as 'no keyboard' flashed the layout). A headless browser can't open a keyboard: the browser check sets those variables by hand, and the real iPhone check covers the rest. The embedded shell (`` ` `` key) is `MiniShell.jsx`. Both frame one `ShellPane.jsx`: the output log (`TermLines.jsx`, `role="log"`) and the prompt under it, kept pinned to the latest prompt (`src/lib/useStickToBottom.js`), with a click focusing the prompt unless it ended a drag-select; `variant` (`term`/`embed`) picks the prompt text (`promptText` in `spec.js`, shared with past prompts), labels and sizing. Both shells' state and keys (sessions, history, autotyped shortcuts, the inline ./egg) live in `components/shell/useShell.js`; a command's effects on the page (open a project, theme, scroll to a section…) come back to App through `onFx` → `applyFx`.
- **App.jsx helpers:** the URLs are the pure `src/lib/urls.js` (`secUrl`, `projPath`/`projUrl`, `parseHash`/`parsePath`); where the page's URL points (`parseLocation`), the scroll lock and quiet focus moves are in `src/lib/nav.js` (`holdNav` sets the jump state to `moving`, its timeout to `landed`, `freeNav` (the user took over) to `none`; `src/lib/jump.js` fires `JUMP_CHANGED`); the j/k selection model (stops, one per experience role) is the pure `src/lib/selection.js` (the key router calls it for j/k); keyboard decisions are the pure `src/lib/keyRouter.js` (`test/keys.test.mjs`). `test/nav.test.mjs` covers the URL parsing (`urls.js`) and the selection model; the DOM helpers in `nav.js` (`holdNav`, `alignTarget`, `focusQuiet`, `keepAligned`) are untested (the browser check pins `keepAligned` through the egg's park).
- **Egg minigame**: `components/egg/useEggGame.js` runs one rAF loop that draws into the hero `<pre>` or the terminal's inline one. Per-frame state stays in refs, never React state; only stage/result/stats are state. During a round (stages 1–4) the game logic runs every frame whether or not the pot is on screen (only the raster is skipped); at rest (stage 0 or 5) the loop idles while the pot is off screen or the tab hidden, and any scroll, resize, key, pointer, popstate, stage or mode change wakes it. Every per-frame step is scaled by elapsed time, so speed doesn't depend on the display's refresh rate. The character grid (resolution) comes from `ui.eggFontPx` via `src/lib/egg/grid.js`; smaller font = more cells in the same frame.
- **Egg on a phone** (≤600px, touch; `CONTEXT.md` "held"): the hero's egg panel is exactly the band between the bars (`100svh − --nav-h − --bar-h`: svh, not dvh, so Safari's toolbar can't resize the pot mid-round; the header keeps its 108px for the result's stats, the pot scales to what's left through `--egg-scale`). Starting a round scrolls its top to just under the nav (`parkEgg` in `App.jsx`, called from `startEgg` at stage 0, so a tap and the keyboard alike; never from the later pull / play-again presses, which are timed and must not move the page; the panel's own `scroll-margin-top: var(--nav-h)`, not a section jump's `--nav-offset`, whose 26px would come out of the band); the embedded shell's `./egg` does the same (and only `./egg`: `cd ~` still goes to the top of the hero), from a project page too (once the hero is back). The hero can still settle after the page lands (measured on a loaded machine: +40px, then back, and the browser's scroll anchoring moves the scroll with it but not back), so `keepAligned` (`src/lib/nav.js`) re-parks the panel for 1.5s whenever the hero or page changes size and on a short timer ladder, until the visitor scrolls or presses something (an event that began before the park doesn't count: the Enter that ran `./egg` is still on its way to `window` when React lands the leave inside that dispatch, and it once stopped the re-park at once: a load-dependent flake, 6 in 16 under CPU load, 0 in 16 after); a smooth park is left alone for its first 500ms so the re-park doesn't cancel it, and a new park replaces the old one. A completed tap in the egg frame **holds** it (`src/lib/egg/held.js`, applied in `useEggGame`; a mouse never does; held on `pointerup` inside, because a swipe that starts on the pot is scrolling the page and ends in a `pointercancel`, and holding on `pointerdown` left the next swipe turning the egg: a scroll trap; a touch landing outside lets go at once): the pot's `touch-action` goes `pan-y` → `pinch-zoom` (`[data-held] .pre`), so one finger turns the egg and the page doesn't scroll from the pot, while drags anywhere else still scroll (no page lock, so no trap); a thin outline shows it. A touch outside the frame, the round ending, or leaving the gui (`egg.release()`; the terminal block also releases when it unmounts) lets go; the pot scrolling off screen doesn't. Terminal mode's inline `./egg` is the same on touch (`components/shell/TermEgg.jsx`): a tap on the pot only holds it, the stages are buttons under it plus `quit` (no ctrl-c on a phone), the key-hint lines leave the status text, which wraps (its title line is ~76 characters), and the block fills the visible output area (`src/lib/egg/fit.js`: the pot scaled to what's left after the measured status (CSS reserves its tallest, 9 lines), the buttons and padding, floor 50%). It ends above the area's bottom padding so the shell's pin-to-bottom on focus lands where the block already is (a 23px jump between press and release once sent a button's click to the wrong element), and it aligns its own top to the area's top on mount, every resize, `visualViewport` change and scroll, because iOS gives the screen back to the page in steps after a keyboard closes and the shell's pin lets go mid-change. On touch a shortcut tab only plays its typing animation (it never focuses the prompt: that opened the keyboard) and starting `./egg` puts an open on-screen keyboard away (only while the frame is marked `data-kb`: an iPad with a hardware keyboard counts as touch but has none, and its Enter and ctrl-c need the prompt). The block marks itself `data-no-focus` so the shell pane's click-to-focus skips it. The phone panel has a 360px floor so a short narrow desktop window can't squash it. Pinned by the browser check (`phone egg…`, `embedded ./egg…`, `phone terminal egg…`, `the egg frame is unchanged on a desktop`).
- `src/app/{projects,experience,skills}/page.js` are redirect stubs to the matching anchor (static export has no server redirects): `components/Redirect.jsx`, a meta refresh plus a link, no client code, `noindex`. The layout carries a schema.org Person (JSON-LD).

## Conventions

- **Path alias**: `@/*` → `src/*` (see `jsconfig.json`).
- **Styling**: CSS Modules per component. Five theme tokens (`--bg --fg --mid --line --soft`) in `src/app/globals.css`, switched by `<html data-theme>` via `src/lib/useTheme.js`; default is dark (ink). Radius 0, no shadows except the embedded shell and the popups. Font is IBM Plex Mono, self-hosted from `src/app/fonts/plex/` via `next/font/local` (`--font-plex`), with JetBrains Mono Regular as a per-glyph fallback for the few symbols Plex lacks (■ □ ●); both have a 0.6em advance, which the ASCII art and egg grid assume. `--mono` is the stack. Two weights only: 400 and 500 (headings); there is no bold, and `font-synthesis: none` stops the browser faking one. Don't use Google-hosted fonts: their subsets drop the box-drawing/block glyphs (U+2500–259F). Plex has no ↵ or ★, so use ↲ for Enter. **Casing is stored exactly as displayed** (no `text-transform`, no JS case changes), so the gui and terminal always match: the site's voice is lowercase, including Danny's name, his own project names, job titles, dates and locations ("waterloo, on"); external entities keep their normal casing (companies, schools, events, products and tech: IESO, City of Waterloo, UofTHacks, GitHub, Next.js) as do acronyms (OCR, AI, BBA, UTC).
- **React Compiler is on** (`reactCompiler: true` in `next.config.mjs`, `babel-plugin-react-compiler`): it memoizes components, hooks and JSX at build time, so an embedded-shell keystroke re-renders only the shell (measured). Keep it effective: build big JSX pieces outside conditionals (App.jsx builds `header`, `hero`, `projectList`… up front; `ProjectDetail` and `Terminal` stay inline because each is a single element that depends on `view`/`mode`), don't read the clock or other impure values during render, and never add an `eslint-disable` for a react-hooks rule (the compiler then skips that whole component or hook).
- **Lint rules**: eslint-config-next 16 enables the React Compiler hook rules (`refs`, `set-state-in-effect`, `immutability`, `purity`). `no-undef` is on too (`eslint.config.mjs`; Next's config leaves it off), so a name a rename left behind fails lint. Pass refs as top-level `*Ref` props (not nested in objects), and set state from callbacks, not synchronously in effect bodies. **ESLint 10 runs with two workarounds in `eslint.config.mjs`** because `eslint-config-next` 16.3.8 and its plugins (`eslint-plugin-react` 7.37.5, `import` 2.32.0, `jsx-a11y` 6.10.2) don't declare ESLint 10 support yet: JS/JSX files use ESLint's own parser (`espree`, a direct devDependency) because Next's bundled Babel parser crashes on ESLint 10, and `settings.react.version` is pinned because `eslint-plugin-react` autodetects it through `context.getFilename()`, which ESLint 10 removed. Remove both once those packages release ESLint 10 support (check `npm view eslint-config-next peerDependencies` and the plugins' peer ranges); a plugin that starts calling another removed API fails loudly (a crash on lint), not silently.
- **Current role**: an experience entry's `now` (the `● now` badge) is derived from its `date` against the build date (`BUILD_DATE`, `env` in `next.config.mjs`), and the hero/whoami `working` fact shows only while its `org` has a current role, so the daily deploy retires both the day after a term ends.
- **Data**: All content is hand-authored in `src/data/` (`projects.js`, `experience.js`, `home.js`, `egg.js`) and `src/config/` (`site.js`, `ui.js` for design options + shortcuts). There is no CMS.
- **Skills**: `coreTechStack` in `src/data/home.js`. A skill's bar = share of projects whose `tags` include it (exact or prefix word). Skills used by no project show `coursework`; list the courses in that item's `courses` array.
- **Reduced motion** (`CONTEXT.md`): reduce, don't remove. `src/lib/useReducedMotion.js` reads the OS preference, and only what moves across the screen honours it: jumps are instant (`App.jsx` `smooth`), no view fade, no intro reveal sweep (the page is uncovered at once), no cursor morph/spin (`Cursor.module.css`), and the 404 egg holds one still frame. Everything else plays as usual: type-ins (only `ui.headerFx: "none"` turns them off), the intro's boot log, blinking carets, shell auto-typing, the press flash and the egg (a Windows PC with Animation effects off showed a frozen, "stuck" site before). `npm run check:browser` pins both lists.

## Commands

```
npm run dev           # local dev server
npm run lint          # eslint . (fails on any warning)
npm run format        # prettier --write .
npm run format:check  # prettier --check .
npm test              # node:test suites in test/ (pure libs + data checks)
npm run build         # next build → out/
npm run sync          # refresh the build-time GitHub snapshot
npm run check:browser # drive out/ in headless Chrome (after npm run build; ONLY=<case> runs one)
```

**Deploys.** `.github/workflows/pages.yml` runs `lint`, `format:check`, `test` and `build` and deploys `out/` with GitHub's Pages artifact actions on every push to `main`, daily at 09:17 UTC (refreshing the GitHub snapshot; the previous snapshot is restored from the actions cache first, so an API failure keeps the last good data) and on `gh workflow run pages.yml`. Settings → Pages → Source must be **GitHub Actions**. A red check on `main` means nothing was deployed. There are no pull-request checks and no Dependabot: dependency and action bumps are by hand (see the lockfile rule below). GitHub disables scheduled workflows after 60 days with no repo activity, which would silently stop the daily deploy (and the `● now` retirement it drives); `gh workflow enable pages.yml` turns it back on. Node version: `.nvmrc`.

**Tests** (`test/*.test.mjs`) import the app's modules unchanged through `test/hooks.mjs`, which resolves `@/` and extensionless imports like Next does and loads `src/**/*.js` as ESM. Keep the pure libs free of DOM and React so they stay testable. What reads the page or browser storage (the intro plan, the reveal, when sections type in, reduced motion) is pinned by the browser check instead. The coursework test is a `todo` until the `courses` arrays are filled.

**Browser check** (`scripts/browser-check.mjs`, `npm run check:browser`, local only, not in `pages.yml`): serves `out/` at `/Portfolio/` (unknown paths get `404.html`, like Pages) and drives headless Chrome over the DevTools protocol, no dependencies (`CHROME=` picks another binary). It pins what node tests can't: when sections type in (scrolling down and up, the 120px offset, keyboard jumps starting their target at once, sections passed or peeking below a jump waiting, Tab, the shell's `cd`, a wrapped nav at 400px, a phone jump, the phone's one-row bars and menu at 390/360/320), no key labels on a touch screen (and the 16px prompt) and key labels on desktop, the intro (the reveal, Enter skipping it, scrolling during it), a smoke run (project open and back, theme, keys popup, terminal mode, deep link, 404, egg) and reduced motion; any console error fails it. Each case gets a fresh tab (a hash-only navigation doesn't reload the page).

**Lockfile:** write it only with CI's npm (`npx npm@11.19.0 install --package-lock-only`). A local `npm install`/`npm prune` with another npm version drops the `@emnapi/*` entries and `npm ci` then fails in CI.
